# 1. V1 JSX Grammar (contains artifacts, use current Chimera+ style guide and CrabsTK/Hatch)

## Supported

  <root>...children...</root>
  <root attr="static" dyn={var}>...</root>
  <root/>                          (self-closing, no children)
  <parent><child/><child2 attr="v">text</child2></parent>

  - Exactly one root element.  Whitespace before/after the root is allowed
    and consumed.
  - Tag names: [a-zA-Z][a-zA-Z0-9:_-]*  (lower and upper case both valid;
    uppercase tags are just tag names, not component references).
  - Attributes:  name=value  where name is [a-zA-Z_][a-zA-Z0-9_]*  and
    value is either:
      "static string"   double-quoted, no escapes in v1 (raw bytes)
      {identifier}      identifier-only dynamic binding, resolved from the
                        caller's context at render time
  - Text children: raw bytes between > and the next < or </.  Internal
    spaces are preserved (semantic spaces).  Leading/trailing whitespace
    on a text run that is purely whitespace is dropped; mixed runs keep
    their internal content.
  - Self-closing: <tag/>  or  <tag attr="v"/>
  - Nested elements: children are parsed recursively, depth-bounded.

## Explicitly rejected (byte-offset diagnostic, rc = -3)

  - Empty tag:          <            (no name before >)
  - Mismatched close:   <a></b>
  - Unclosed element:   <a>text       (EOF before </a>)
  - Self-close junk:    <a/>trailing
  - Unterminated quote: <a x="unterm  (no closing ")
  - Unterminated brace: <a x={var     (no closing })
  - Empty brace:        <a x={}
  - Non-identifier in {}:  <a x={a.b}  <a x={f()}  <a x={a ? b : c}
  - Spread:             <a {...rest}
  - Fragment:           <>...</>
  - JSX comment:        {/* comment */}
  - Trailing garbage:   </a> extra    (after root close, non-ws bytes)
  - Depth limit:        > 64 nested elements
  - Element limit:      > 4096 total elements
  - Source limit:       > 65536 bytes

## Whitespace / text semantics

  - Whitespace between the root's > and its first child: consumed, not
    emitted.
  - Whitespace between a child element and the next sibling: if the text
    run between them is pure whitespace (spaces/tabs/newlines only), it is
    dropped.  If it contains non-whitespace, the full run is emitted as a
    text child (internal spaces preserved).
  - Example:  Hello <b>bold</b> world
    → text "Hello "  +  <b>bold</b>  +  text " world"
    (the space before <b> and after </b> are kept; they are part of
    mixed text runs, not pure-whitespace inter-element gaps).

  This matches the Preact/JsxCore reference:  <h1 className="title">
  Hello {model.name}</h1>  renders  <h1 class="title">Hello World</h1>
  (the space before the binding is preserved as a text node).

# 2. Emitted Builder Contract

## Function signature

  Each JSX source file Foo.jsx produces an includable C++ header with:

    inline ISC BuildFoo(TJsx<ISC, ISC, DTB, CHR, CHR, IUC>* j,
                        ISC ctx, ISC* out_root)

  - Returns 0 on success;  *out_root is a valid tree root index (>= 0).
  - Returns negative ISC on any failure (alloc exhaustion, invalid engine
    pointer, out_root nil);  *out_root is set to -1 before any work.
  - No extern "C" (single TU, C++ template pointer).
  - No main, no new/delete, no printf, no static state, no hardcoded
    user data, no hidden heap.
  - The caller owns the TJsx engine instance and the context.  The caller
    calls j.Init(buf, bytes, total) and j.NewContext(vars) before calling
    BuildFoo.  The builder does NOT call Init or NewContext.
  - Two builders in one TU: distinct names (BuildFoo, BuildBar) — no
    collision.  The name is Build + CamelCase(source_filename_stem).

## Emitted code structure

  // Generated by JsxToCpp — do not edit.
  // Source: <div class="box"><span data={name}>Hello</span></div>
  #pragma once
  #ifndef _CrabsTKJSXExampleHXX
  #define _CrabsTKJSXExampleHXX
  #include <_Seams.hxx>
  #include "Jsx.hxx"
  namespace CTK {
  inline ISC BuildFoo(TJsx<ISC, ISC, DTB, CHR, CHR, IUC>* j,
                      ISC ctx, ISC* out_root) {
    if (!j || !out_root) return -1;
    *out_root = -1;
    ISC el0 = j->AddObject(ISC(65536), ISC(64), ISC(4096));
    if (el0 < 0) return -2;
    j->SetTag(el0, (const CHR*)"div");
    j->SetProp(el0, (const CHR*)"class", (const CHR*)"box");
    ISC el1 = j->AddObject(ISC(65536), ISC(64), ISC(4096));
    if (el1 < 0) return -3;
    j->SetTag(el1, (const CHR*)"span");
    j->SetDynProp(el1, (const CHR*)"data", (const CHR*)"name");
    j->AddText(el1, (const CHR*)"Hello");
    j->SetChild(el0, el1);
    *out_root = el0;
    return 0;
  }
  }  // namespace CTK
  #endif  //< JSXGEN_BUILDFOO_HXX

## Caller usage (the app / test TU)

  #include "Jsx.hxx"
  #include "BuildFoo.hxx"       // generated
  #include "BuildBar.hxx"       // generated — coexists in one TU

  ISC main() {
    static alignas(64) CHR buf[1 << 30];   // 1 GB arena, caller-owned
    TJsx<ISC, ISC, DTB, CHR, CHR, IUC> j;
    j.Init(buf, sizeof(buf), ISC(1 << 20));
    ISC ctx = j.NewContext(ISC(16));
    j.SetVar(ctx, (const CHR*)"name", (const CHR*)"Captain");
    ISC root = -1;
    ISC rc = BuildFoo(&j, ctx, &root);
    if (rc != 0 || root < 0) return 1;
    CHA out[4096];
    ISC n = j.Render(out, ISC(4096), ctx, root);
    // ... use out[0..n) ...
    return 0;
  }

## Memory model

  - The TJsx stack IS the arena.  One caller-owned contiguous buffer.
    No heap, no new/delete, no smart pointers.
  - Each AddObject is a TListAlloc on the stack — bounded by the
    caller-provided buffer size.
  - Each PutString (inside SetTag/SetProp/SetDynProp/AddText) is a
    TListAlloc + copy — bounded by the buffer.
  - Profile first: use generous per-node allocs (65536 bytes / 64 keys /
    4096 key-bytes) to get data on real usage, then tune.  64 GB RAM
    available; the buffer can be as large as the app needs.
  - The builder is pure: it reads compile-time string literals (baked in
    by the transformer) and calls AddObject/SetTag/SetProp/SetDynProp/
    AddText/SetChild against the passed-in engine.  No state, no I/O.

## C++ literal escaping (transformer-side, NOT renderer-side)

  The transformer escapes string payloads when baking them into C++
  literals.  The renderer (Illya's lane) does HTML escaping.  These are
  separate concerns:

  Transformer C++ literal escaping:
    \  →  \\
    "  →  \"
    \n →  \n   (actual newline byte → C++ escape)
    \r →  \r
    \t →  \t
    0x00-0x1F (other control)  →  \xNN
    0x7F (DEL)                 →  \x7F
    0x80-0xFF (UTF-8 bytes)    →  preserved as raw bytes

  Renderer HTML escaping (Illya's contract, not implemented here):
    &  →  &amp;
    <  →  &lt;
    >  →  &gt;
    "  →  &quot;  (in attribute values only)

  The transformer does NOT do HTML escaping.  A JSX source containing
  <b>bold</b> in a text child is baked as the C++ literal "bold" (the
  <b> is a nested element, not text).  A JSX source containing the
  literal string "a & b" in a prop value is baked as the C++ literal
  "a & b" (ampersand is not a C++ special CHR).  The renderer will
  escape & to &amp; when emitting HTML.

# 3. Defect List (all confirmed in AGENT_PLAN §2, all in current source)

  D1. capacity64 overwrites byte64, returns success.
      Fix: bound every writer, reserve the terminator byte, return
      explicit overflow (rc = -4) when out_n + needed > out_cap - 1.

  D2. Malformed input (mismatched/unclosed/unterminated/trailing)
      succeeds with rc=0.
      Fix: strict validation of every construct; byte-offset diagnostic
      on first failure; rc = -3 on any parse error.

  D3. child_idx % 10 links root to itself at 12+ elements.
      Fix: full numeric node IDs (el0, el1, ..., el10, el11, ...).
      var_name() emits the full index, not idx % 10.

  D4. C++ string payloads copied without escaping.
      Fix: dedicated escape_literal() in the emitter.  Quotes,
      backslashes, control bytes, newline are escaped.  UTF-8 bytes
      preserved.

  D5. Semantic spaces trimmed.
      Fix: preserve internal spaces in text runs.  Only pure-whitespace
      inter-element gaps are dropped.  Hello <b>bold</b> world keeps
      both spaces.

  D6. Generated code owns main/new/delete/printf, hardcodes name=Captain.
      Fix: emit an includable builder function.  No main, no new, no
      delete, no printf, no hardcoded user data.  Caller owns engine,
      context, arena, and output buffer.

  D7. (Noted, not fixed here) NewContext(16) allocates 256 key bytes,
      TDicInit fails for that config.  This is Illya's P0.  The builder
      does NOT call NewContext — the caller does.  The builder's
      SetDynProp calls store the var name; the context is resolved at
      render time by the renderer.  If Illya changes NewContext sizing,
      the caller (not the builder) is affected.

# 4. Public API — JsxToCpp (unchanged entry point, additive diagnostics)

  inline ISC JsxToCpp(const CHA* source, ISC source_len,
                      CHA* out_buf, IUD out_buf_len,
                      TJsxTransformResult* out_result)

  Returns:
    0   success (out_result->output contains the emitted C++ source)
    -1  invalid arguments (nil source/out_buf/out_result, or out_buf_len < 256)
    -2  source too long (> 65536 bytes)
    -3  parse error (out_result->first_error + out_result->error_offset
        give the byte offset and a static message)
    -4  output buffer overflow (emitted C++ would exceed out_buf_len)

  TJsxTransformResult (existing fields, additive):
    CHA* output;            //< Emitted C++ source (caller-owned buffer).
    ISC  output_len;        //< Length in bytes (NUL-terminated).
    ISC  element_count;     //< Number of elements in the JSX tree.
    ISC  error_count;       //< Number of parse errors (0 or 1 in v1:
                            //< first error is fatal, parsing stops).
    const CHA* first_error; //< Static message or "".
    ISC  error_offset;      //< NEW: byte offset of the error in source.
                            //< -1 if no error.

# 5. CodeLexer / CodeFit Tooling Adapter (for the verification lane)

  The JSX pair is intended for ASCIICrabs.  Code/Lexer.h and Code/Fitter.h
  live in CrabsTK.  The adapter is a tooling/test concern, not a runtime
  dependency.  No CrabsTK include is added to the reusable headers.

  When the verification lane runs (Madyar's runner or a dedicated tooling
  TU), the minimal adapter call sequence is:

    1. Read the emitted C++ source from JsxToCpp's output buffer.
    2. Pass it to CodeLexer (TFitting / CodeLex) to tokenize.
    3. Pass the token stream to CodeFitter (CodeFit) to canonicalize.
    4. Compare the fitted C++ to the original: semantic equivalence
       (same tokens, same order, whitespace/indentation may differ).
    5. Compile both original and fitted C++ into separate TUs.
    6. Run both; compare rendered HTML byte-for-byte.

  This establishes that fitting is a formatting transform, not a semantic
  one.  The adapter is not implemented in JsxTransform.hxx; it belongs in
  the verification lane.
