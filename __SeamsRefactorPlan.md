# __Seams Refactor Plan — hierarchical module seams
Date: 2026-10-27 · Status: EXECUTED (verified 2026-10-27: ad-hoc suite 17/17, rollup green, ASan clean) · Owner: low-level agent + Cale

## 1. Problem audit (what's on fire)

1. **Root `__Seams.yaml` (40 seams) does not match the generated `_Seams/_Seams.h`.**
   The generated table starts with 18 `CRABS_*` core seams (RNG/ITOS/FTOS/…
   FILECABINET = 18) then `CRABSTK_WHO_CORE = 19` — that table came from an
   OLDER yaml. The current `__Seams.yaml` has one `CRABS_CORE` + Who/Pro/Code/
   Imul/Data/Plot/Touch/Gui/Env/Release (40 seams). Two yamls, one tree.
2. **Root yaml is missing modules**: Audio, Crab, Forms, Image, IPC, Math, Web,
   Hatch have no seams listed; `Pro` is listed (8 seams) but excluded from
   `_Package.hxx` (does not compile — deleted Script2 API).
3. **Case-duplicate module folders**: `_Seams/Gui/` AND `_Seams/GUI/`,
   `_Seams/Imul/` AND `_Seams/IMUL/`. Code dirs are `GUI/` and `IMUL/`; the
   yaml uses `module: Gui` / `module: Imul` (the non-code dirs).
4. **No folder metadata**: module code lives in `<Module>/` at the root
   (Audio, Code, …) but IPC code+seams live in `IPC/`, Math code in `Math/`
   (standalone tests, no seams dir), and the ASCIICrabs dependency is a
   sibling. Include paths are implicit in build commands.
5. **Generated files were hand-edited after generation**: the real
   `_Seams/_Main.hxx` carries `COut.h/AType.hxx/Array.hxx/Puff.hxx/Test.hpp/
   Test.hxx/Stringf.hxx` includes the generator never emits. The generator
   cannot be re-run without destroying those edits — so nobody re-runs it.
6. **`00.Core.hxx` is fully generated** ("Your test code here" placeholders):
   any re-sync overwrites hand-written test bodies. This is the tedium trap —
   the reason the yaml got slopped out by hand instead of through the tool.
7. **Three independent seam trees** (`_Seams/Data/`, `_Seams/Plot/`,
   `IPC/_Seams/`) each carry their own `_Config.h`/`_Main.hxx`. Data's is
   verified PASS end-to-end; they work but are parallel universes.
8. **Clutter**: `_Seams/desktop.ini`, `_Seams/CMakeFiles.txt`, stale
   `Release.h`, case-dup folders.

## 2. Target architecture

```
CrabsTK/__Seams.yaml                  # ROOT: module list only (order + folder:)
_Seams/<Module>/__Seams.yaml          # module's own seam list (today's seams: schema)
_Seams/<Module>/00.Core.hxx           # module test entry: generated skeleton + user bodies
<Module>/                             # module code, default layout; folder: overrides
```

Root yaml lists MODULES, not seams. Each module folder carries its own
`__Seams.yaml` listing its seams (the exact schema the parser already
understands). The root file says which modules exist, in what build-up order,
and (optionally) where each module's code/seams live.

### 2.1 Root `__Seams.yaml` schema (new)

```yaml
project: CrabsTK
mode: crabstk
release_module: Release          # terminal module, always last

modules:
  - name: Data                   # list order = build-up order (explicit wins)
    label: "Data module"
  - name: IPC
    folder: IPC/_Seams           # optional; default _Seams/<name>
  - name: Math
    folder: Math/_Seams
  # ... remainder alphabetical ...
  - name: Release
    folder: _Seams/Release
```

Rules:
- **List order is the seam build-up order.** Default scaffolding is
  alphabetical; modules that must work first are written at the top.
- **`folder:`** — path relative to the directory containing the root yaml,
  pointing at the module's seam directory. Covers sibling
  (`../ASCIICrabs`), parent-sibling-child (`../../Shared/Seams`), child
  (`Sub/Seams`). When set, the generator (a) reads `<folder>/__Seams.yaml`,
  (b) writes `<folder>/00.Core.hxx`, and (c) emits the folder's include dir
  into the generated `_Config.h` include-path comment block (and CMake
  `include_directories` when present) so the build knows where the code is.
- **`release_module:`** — the final "sown" module, always placed last,
  carrying the last integrated test pass. `SEAM_N` = its last seam; the
  Core→Release range is the full 1..N table.

### 2.2 Module `__Seams.yaml` schema (unchanged, per module)

```yaml
seams:
  - name: CRABSTK_DATA_RECORD
    label: "Testing Data record..."
  - name: CRABSTK_DATA_DATASET
    depends: [CRABSTK_DATA_RECORD]     # optional, name-based
```

Numbering: global monotonic 1..N = module order × module-seam order. Inside
a module, `depends` still topologically orders (existing Kahn logic); a seam
may only depend on an EARLIER module or its own module (generator validates).
Seam NAMES stay stable; numbers are regenerated by the reordering (this
reorder is the one sanctioned exception to "never renumber"; afterwards, new
seams append at the end of their module list — gaps allowed, reuse never).

### 2.3 Generator changes (`Hatch/SyncSeams.py`)

1. Schema detection: root yaml with `modules:` → hierarchical path; `seams:`
   → legacy flat path (ASCIICrabs and generated scaffolds keep working
   unchanged).
2. Load each `<folder>/__Seams.yaml` with the existing `LoadSeams`; order
   within module; concatenate in module order; enforce release last.
3. Output shape unchanged: root `_Seams/_Seams.h`, `_Seams/_Config.h` (adds
   the folder-derived include-path block), `_Seams/_Main.hxx` (per-module
   includes + full TTestTree list — including the COut/AType/Array/Puff/Test
   includes the real entry needs, moved from hand-edit into the generator).
4. **Merge-safe `00.Core.hxx`**: skeleton lines (gating includes, namespace,
   function signatures, `return NILP;`) are regenerated; user code between
   `// SYNC-KEEP-BEGIN` / `// SYNC-KEEP-END` inside each test function is
   preserved byte-for-byte. First run seeds markers around any existing
   non-placeholder body, so re-syncs are safe and the tedium trap is gone.
5. Validation: missing module folder/yaml, duplicate seam names across the
   whole table, cross-module depends pointing at a later module, release not
   last, unresolvable `folder:` targets — hard errors with the offending
   module named.

## 5. What this is NOT

- Not a renumbering policy change for future seams (append-only, names
  stable, reuse never).
- Not a change to the ASCIICrabs flat yaml (it stays legacy-flat mode).
- Not touching the frozen `00.Core.hxx` Doxygen/MPL headers or the
  independent Data build's internal layout.
- Not fixing the pre-existing breakages listed in the 2026-10-27 session
  report (root-app FPC collision, 05.Clock, BSeq/Slot, truncated
  `_Config.h`) — orthogonal, tracked separately.
